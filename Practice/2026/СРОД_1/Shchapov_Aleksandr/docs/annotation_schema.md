# Аннотационная схема

ЛР2 «Проектирование аннотационной схемы». Тема: «Оценка гитар по текстам, изображениям и аудио».

Состав документа следует шагам 1–7 методички, печатные с. 46–51. Таблица уровней построена по образцу таблицы 8.2.1, с. 48. Полная разметка выполняется в ЛР3–5; здесь заданы её требования.

## 1. Состав схемы: группы объектов и модальности

Объект корпуса — **модель гитары с указанной версией**, а не доказанно один физический экземпляр. Все три материала принадлежат одному обзору этой модели. Всего 10 объектов, `GTR001`–`GTR010`.

| Модальность | Гитара | Детали: звукосниматель, бридж, управление | Звучание |
|---|---|---|---|
| Текст | Название модели и версия | Название, тип, положение и назначение детали | Описание условий записи и подтверждённой последовательности переключений |
| Изображения | Рамка инструмента | Рамки видимых деталей; положение звукоснимателя | Не размечается: по фотографии звук не определяется |
| Аудио | Ссылка на модель через ID | Активный датчик/режим, только если это подтверждено | Музыкальные фразы, интервалы звучания и паузы |

Текст сообщает конструкцию, изображение локализует детали, аудио даёт пример звучания в конкретных условиях. Сходство моделей не означает одинаковых условий записи. Причинные выводы о влиянии древесины и рейтинги качества по этим записям не строятся.

## 2. Уровни аннотаций — по таблице 8.2.1

| Модальность | Уровень 1 | Уровень 2 | Уровень 3 |
|---|---|---|---|
| Структура документа | Документ | Абзац | Предложение |
| Текст | Именованная сущность | Часть речи | Токен |
| Изображения | Область изображения | Гитара | Деталь: звукосниматель, бридж, орган управления |
| Аудио | Запись | Музыкальная фраза | Звуковой интервал: звучание или пауза |

Это уровни детализации, как в методичке. Для текста часть речи является свойством токена; она не является вложенной сущностью. Изображение целиком — исходная область, рамка гитары — объект, рамки её деталей — следующий уровень.

## 3. Сущности, признаки и допустимые значения

### Текст

| Единица / метка | Что выделять | Атрибуты и пример |
|---|---|---|
| `GUITAR` | Полное название модели при каждом упоминании | `guitar_id`; «Reverend Six Gun HPP» |
| `PICKUP` | Название или однозначное упоминание звукоснимателя | `component_id`, `position`, `pickup_type`; «хамбакер HA5» |
| `BRIDGE` | Название бриджа или системы вибрато | `component_id`, `bridge_type`; «Hipshot Ibby HM» |
| `CONTROL` | Регулятор или переключатель | `component_id`, `control_type`; «Bass Contour» |
| Токен + `UPOS` | Каждое слово и отдельный знак пунктуации | Универсальные части речи: ADJ, ADP, ADV, AUX, CCONJ, DET, INTJ, NOUN, NUM, PART, PRON, PROPN, PUNCT, SCONJ, SYM, VERB, X |
| Отношение `HAS_PART` | Связь упоминания гитары с упоминанием её детали | `GUITAR → PICKUP / BRIDGE / CONTROL` |

Словари признаков:

- `position`: `bridge`, `middle`, `neck`, `unknown`.
- `pickup_type`: `humbucker`, `single_coil`, `p90`, `unknown`. Здесь P-90 выделен в отдельную учебную категорию синглов.
- `bridge_type`: `fixed`, `vibrato`, `unknown`.
- `control_type`: `volume`, `tone`, `bass_contour`, `selector`, `unknown`.

Позиция, тип и имя компонента фиксируются по явному тексту. Общие рассуждения о других гитарах не превращаются в свойства выбранной модели. Мнения автора сохраняются в тексте как мнения; отдельные оценки качества и тембра в обязательную схему не входят.

### Изображения

Метки рамок: `GUITAR`, `PICKUP`, `BRIDGE`, `CONTROL` — те же группы сущностей, что в тексте. Для GUITAR указывается только `guitar_id`; у рамок деталей — `guitar_id` и индивидуальный `component_id`; для датчика также `position`. Неприменимые признаки отсутствуют.

Размечается видимая часть детали, без пустого поля вокруг неё. Положение датчика определяется относительно грифа и бриджа, а не относительно левого края кадра. Перекрытую или неразличимую деталь не дорисовывают. Тип катушек, породу дерева и текущую настройку регулятора по внешности не угадывают. Текстовый тип датчика остаётся свойством с текстовым источником, а не наблюдением по изображению.

### Аудио

| Слой Praat | Единица | Допустимые значения |
|---|---|---|
| `phrase` | Музыкальная фраза | `phrase_001`, `phrase_002`, …; пустая метка вне фразы |
| `event` | Звуковой интервал | `playing`, `pause`, `other` |
| `pickup_setting` | Интервал с подтверждённой настройкой | `bridge`, `middle`, `neck`, `bridge+middle`, `middle+neck`, `bridge+neck`, `unknown` |
| `coil_mode` | Интервал с подтверждённым режимом | `full`, `split`, `series`, `parallel`, `unknown` |

Настройка и режим берутся из подписи к конкретному клипу и проверяются по записи. `middle` означает отдельный средний датчик, а `bridge+neck` — два одновременно включённых датчика. Если звучат наложенные партии с разными настройками, общее значение — `unknown`. Поля `recording_chain` и `audio_mapping` в реестре сохраняют известные условия записи; отсутствующие сведения не заполняются предположениями.

Фраза — завершённое музыкальное построение, определяемое при прослушивании. Пауза — отсутствие намеренно сыгранного звука не менее 0,2 с; затухание ноты входит в `playing`. Посторонний звук/речь — `other`. Границу уточняют по прослушиванию и осциллограмме. Минимальную длительность сыгранной ноты искусственно не задают.

## 4. Формальные и содержательные требования

**Общие ID.** `guitar_id = GTR001`; материалы: `GTR001_TXT01`, `GTR001_IMG01`, `GTR001_AUD01`. Детали: `GTR001_PICKUP_bridge`, `GTR001_PICKUP_middle`, `GTR001_PICKUP_neck`, `GTR001_BRIDGE_01`, `GTR001_CONTROL_01`. Для нескольких деталей одного класса используются последовательные номера и описание назначения. Аннотация получает ID, уникальный внутри материала.

**Текст.** UTF-8; файл после начала разметки не редактируется. Координаты `[start, end)` задаются в символах Unicode исходного TXT, начиная с нуля, с учётом переносов строк. Минимум — одно полное слово, максимум — одно предложение; выделяется минимальное полное название без соседней пунктуации. Повторные упоминания размечаются отдельно. Пересечения предметных сущностей не допускаются; одинаковая сущность может включать несколько токенов. При преобразовании из WebAnno/INCEpTION проверяется система смещений, особенно при наличии символов вне BMP.

**Изображения.** Прямоугольник `[x, y, width, height]` в пикселях исходного файла, начало в левом верхнем углу. Ширина и высота положительны, рамка внутри изображения. В Label Studio координаты сохраняются в процентах; при переводе в пиксели используются размеры из `manifest.json`. Вложенность рамки детали в рамку гитары допустима.

**Аудио.** Интервалы `[start, end]` в секундах: `0 ≤ start < end ≤ duration`. Каждый IntervalTier покрывает всю запись; интервалы внутри одного слоя не перекрываются. Слои между собой могут пересекаться. Внутренние границы сохраняются с точностью до 0,001 с; конец последнего интервала равен точной длительности WAV (число кадров / частота), без округления; это точность записи чисел, а не обещание точности слуховой разметки. Для неподтверждённых настроек ставится `unknown`.

**Происхождение.** У материала есть путь, URL, ID, SHA-256 и сведения о преобразовании. Источник утверждения о настройке — описание конкретного аудиоклипа. Формат WAV не восстанавливает качество исходного сжатого потока.

## 5. Форматы и расположение

| Модальность | Инструмент | Формат | Папка |
|---|---|---|---|
| Текст | INCEpTION | CoNLL-U для токенов и POS; WebAnno TSV 3 для сущностей, признаков и отношений | `annotations/text/` |
| Изображения | Label Studio | JSON с прямоугольными областями и признаками | `annotations/images/` |
| Аудио | Praat | TextGrid с четырьмя IntervalTier | `annotations/audio/` |

Для CoNLL-U сохраняются 10 стандартных столбцов; ещё не размеченные поля получают `_`. Текстовые экспорты выполнены в ЛР3; аудио имеет техническую предразметку, требующую прослушивания; изображения размечены в Label Studio (10 фото, 80 рамок), см. `annotations/images/README.md`.

## 6. Примеры на материалах корпуса

- **Текст:** в `data/text/GTR001.txt` первая строка «Reverend Six Gun HPP» имеет координаты `[0, 20)` и метку `GUITAR`, атрибут `guitar_id=GTR001`. Упоминание HA5 связывается с `GTR001_PICKUP_bridge` и с гитарой отношением `HAS_PART`.
- **Изображение:** в `data/images/GTR001.jpg` размером 1200×600 видны три датчика. Датчик, ближайший к бриджу, получает `PICKUP`, `position=bridge`, `component_id=GTR001_PICKUP_bridge`. Одна и та же деталь связывает текстовое упоминание и рамку изображения. Проверочный пример рамки датчика: `[207, 241, 57, 112]` пикселей. Она проверена по изображению; полная разметка рамок сохранена в `annotations/images/label_studio.json`.
- **Аудио:** в `GTR004_AUD01` источник задаёт ориентиры 0:00 — бриджевый датчик, 0:16 — оба, 0:34 — нековый. Поэтому `[0, 16] → bridge`, `[16, 34] → bridge+neck`, `[34, duration] → neck` — предварительные интервалы слоя `pickup_setting`. Это подсказка источника, а не завершённая слуховая разметка: границы и слои `phrase/event` проверяются в ЛР4.
- **Неоднозначность:** у GTR003 в подписи упоминается средний датчик, хотя модель имеет два. Спорному участку назначается `unknown`, пока источник не уточнён. Для GTR006 неизвестная позиция датчика не мешает разметить звучание и паузы.

## 7. Проверка аннотаций

1. Проверить все 10 комплектов: уникальность ID, наличие файлов, контрольные суммы, размеры изображений и длительности аудио. Для этого предусмотрен `code/verify.py`.
2. После экспорта каждой модальности проверить обязательные поля, словари меток и допустимость координат. Затем сверить все размеченные сущности, рамки и интервалы с исходным материалом.
3. Повторно разметить GTR001 и GTR005: другим аннотатором, если он есть, либо тем же исполнителем в отдельном проходе. Сопоставить метки, рамки и границы интервалов; расхождения разрешить по исходнику. Второй вариант является самопроверкой, а не независимой экспертной оценкой.
4. После исправления правил повторно проверить затронутые материалы. Результаты кратко записать в README соответствующей папки: дата, проверенные файлы, найденные и исправленные ошибки.

## 8. Применение в следующих работах

- ЛР3: 10 русскоязычных описаний, токены, POS, предметные сущности и `HAS_PART`.
- ЛР4: 10 полных аудиозаписей, фразы, события и известные настройки. Для начала наиболее информативны GTR001–GTR005.
- ЛР5: 10 фотографий, рамки гитар и видимых деталей.
- ЛР6: классы Guitar, Component, Material, TextMention, ImageRegion, AudioInterval; связи `hasPart`, `describes`, `depicts`, `demonstrates` и ссылки на исходные координаты.

Будущие проверяемые запросы: «Для каких моделей указан бриджевый хамбакер, где он виден и есть ли подтверждённый аудиопример?»; «Какие материалы демонстрируют одновременно бриджевый и нековый датчики?»; «У каких моделей запись есть, но положение датчика неизвестно?». Ответ должен включать модель, источник, рамку или временной интервал, если они размечены.


## 9. Уточнения по результатам текстовой разметки

Короткое название целевой модели допустимо как GUITAR при однозначной отсылке к полному имени. Местоимения не размечаются. Эллиптическое название детали («нековому») допустимо, если контекст однозначно указывает на датчик.

Коллективные упоминания получают `component_id` с `_group_`: например, `GTR001_PICKUP_group_middle_neck`. Это ID группы, а не одной физической детали; положение группы — `unknown`. Однородный тип указывается только по явному тексту; для смешанной группы — `unknown`. Группы и индивидуальные компоненты не объединяются автоматически, а число упоминаний не считается числом деталей. Конкретная рамка в следующих работах должна ссылаться на индивидуальную деталь.

HAS_PART привязывает деталь к ближайшему предыдущему явному упоминанию целевой гитары; связь может пересекать границы предложений. Отсутствующие, спорные, чужие и гипотетические компоненты не получают положительной связи. Бридж и отдельная система вибрато могут иметь разные ID. Предполагаемый тип по торговому названию не заменяет явное утверждение.

Структурный слой Paragraph разделяет заголовок и два абзаца. В текущей штатной сегментации Sentence заголовок включён в первый сегмент; для структуры документа используются явные границы Paragraph. Фактические результаты и ограничения перечислены в `annotations/text/README.md`.


## 10. Уточнения для аудиоразметки

На `pause` и `other` настройки по умолчанию `unknown`, если источник явно не задаёт непрерывный известный режим. `full` не назначается по типу датчика или отсутствию сведений об отсечке. Все четыре слоя покрывают WAV без разрывов, с точным концом файла.

Пакетная сегментация даёт только предложения: тихий сигнал и хвост эффекта могут относиться к `playing`. До прослушивания статус предразметки указывается в аудио-README; метки `phrase_*` в таком комплекте обозначают кандидатов, а не установленные музыкальные фразы. Словарь слоёв не меняется. Один общий проход прослушивания должен уточнить события и крупные завершённые фразы всех десяти записей; повторять разметку GTR001/GTR005 отдельным дополнительным циклом для этой работы не требуется. Независимую проверку не заявляем.


## 11. Уточнения по результатам разметки изображений

Для изображений правило дополнительной повторной разметки GTR001/GTR005 из п. 7.3 заменяется **одним общим визуальным проходом по всем десяти фото** и одной технической проверкой окончательного экспорта. После исправления конкретной ошибки проверяется только затронутое место. Проверка текста этим уточнением не меняется. Выполненная проверка изображений является самопроверкой, не независимой экспертной оценкой.

Отдельная рамка никогда не получает ID с `_group_`. Для различимых деталей без однозначного индивидуального соответствия тексту назначаются новые стабильные ID без конфликтов с существующими. Положение новых пронумерованных CONTROL перечислено в README изображений. Одинаковые ручки не отождествляются с volume/tone/Bass Contour по внешности. Для GUITAR component_id не создаётся.

Прямоугольник охватывает видимую конструкцию. Раздельные бридж и вибрато могут иметь разные рамки и ID. Составной неразделимый на фото регулятор размечается как один видимый узел. Не входящие в четыре класса гнёзда и струнодержатели отдельно не размечаются.
